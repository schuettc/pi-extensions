# pi-hail Extension Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@schuettc/pi-hail`, a pi coding-agent extension that connects each interactive pi session to the local hail daemon, streams the session's events, applies phone-originated prompts as typed input, shows phone presence in the status line, and soft-locks each side against the other — so a pi started on the Mac appears on the phone and takes a prompt from it.

**Architecture:** One long-lived NDJSON connection per pi process to the daemon's Unix control socket (contract C4). The extension entry (`src/index.ts`) owns only the pane it starts on (`ctx.mode === "tui"`), captures the session identity at `session_start`, and drives a pure `Session` controller. The controller holds all logic — register handshake, event forwarding, turn markers, the soft-lock state machine, prompt injection, presence→status, replay-after-reconnect, version handshake — behind injected dependencies (socket writer, `pi.sendUserMessage`, `ctx.ui`, a session-file reader), so every behaviour is unit-testable against a fake socket with no real daemon. The socket client (`src/socket.ts`) owns framing, the register round-trip, and reconnect-with-backoff, and never blocks pi: if no daemon answers, the extension stays quiet and retries.

**Tech Stack:** TypeScript (ESM, `.ts` sources run directly by pi and by `node --test`), `node:net` for the Unix socket, `node:readline`/manual newline framing for NDJSON, the `@earendil-works/pi-coding-agent` extension API. No runtime dependencies. Tests use `node --test` with in-process fakes.

**Spec:** `hail/docs/superpowers/specs/2026-09-10-hail-regroup-3-design.md` §4 (the extension and the broker) and §5 (keys / New Task, for context only — the extension never handles keys). Contracts: `hail/docs/superpowers/plans/2026-09-10-hail-regroup-3-coordination.md` C4 (extension↔daemon wire protocol) and C6 (version handshake). Kickoff: `hail/docs/superpowers/kickoffs/regroup3-extension.md` and `regroup3-COMMON.md`.

- **Scripts:** `"typecheck": "tsc --noEmit -p tsconfig.json"`, `"test": "node --test src/*.test.ts"`. Must pass the monorepo root `npm run typecheck` and `npm test --workspaces`.
- **devDependencies:** `@earendil-works/pi-coding-agent` (match the version pinned by sibling packages — currently `^0.84.3`) and `typescript ^5.6.0`. No runtime deps.
- **Explicit identity at spawn (family rule):** capture the pi session id, cwd, project and work name at `session_start` from the event context; pass them through function arguments. NEVER read or write `process.env` for identity (the channels.tools / pi-quiet precedent: `feat/session-identity-at-spawn`). The daemon-spawn signal (tmux window name) is read once at start, not exported.
- **Never block pi:** every handler is best-effort and wrapped so nothing thrown escapes into pi (the `safe()` pattern from `pi-tmux-bridge/src/index.ts`). No socket call is awaited on pi's critical path; a missing/slow daemon must never stall a turn.
- **Own only your pane:** guard every handler with `ctx.mode === "tui"`. Subagent sessions and headless `pi -p` runs load this extension too and must be inert (the `ownsPane` gate from `pi-tmux-bridge`).
- **Security defaults secure; convenience opt-in.** A version mismatch, an unverified state, or an unknown daemon reply refuses rather than proceeds.
- **Wire format (C4):** newline-delimited JSON, one object per line, over the Unix socket `$XDG_RUNTIME_DIR/hail/daemon.sock`, falling back to `$TMPDIR/hail/daemon.sock` on macOS. Long-lived connection per pi process.
- **Version handshake (C6):** send `extensionVersion` (the npm package version) in register; render a version-mismatch refusal as a single one-line notice in pi and go inert.
- **Release:** publish by pushing tag `pi-hail-v<version>` (matches `.github/workflows/release.yml`). First publish is a one-time manual `npm publish` by a maintainer to establish the npm Trusted Publisher; tags handle every publish after. Do NOT add secrets or edit the release workflow.
- **Tests name their failure:** every test's name or first-line comment states the customer-visible failure it guards (COMMON rule). No test is written for behaviour outside this document.
- **Findings outside this plan** go in the Ledger at the bottom, not chased.

## Wire Protocol Reference (C4, verbatim)

Extension → daemon, first line:
```json
{ "cmd": "session.register", "args": { "sessionId": "<pi session id>", "project": "acceptance", "work": "first-run", "dir": "/abs/dir", "piVersion": "0.85.1", "extensionVersion": "0.1.0" } }
```
Daemon reply (success): `{ "ok": true, "data": { "hostId": "...", "daemonVersion": "0.3.0", "accepted": true, "have": <deviceSeq|absent> } }`
Daemon reply (mismatch): `{ "ok": false, "error": "version_mismatch: daemon 0.3.0 requires extension >= 0.1.0" }`

Then, one JSON object per line, both directions:
- **extension → daemon:** `{ "event": <pi rpc event verbatim> }` · `{ "turn": "start" | "end" }` · `{ "lock": "held" | "released" }` · `{ "exit": { "code": n } }` · `{ "refused": { "requestId": "...", "reason": "turn_running" } }`
- **daemon → extension:** `{ "prompt": { "text": "...", "from": "<phoneDeviceId>", "requestId": "..." } }` · `{ "presence": { "phones": [ { "deviceId": "...", "name": "iPhone", "state": "connected" | "driving" | "offline" } ] } }` · `{ "answer": { "requestId": "...", "value": ... } }` · `{ "ctl": "stop" }`

Soft lock: extension refuses a `prompt` while its own (local) turn runs with `{ "refused": { "requestId", "reason": "turn_running" } }`; while a phone-originated turn runs, the extension shows "phone is working" and holds local terminal input behind a visible notice rather than dropping it. `have` in the register reply is the daemon's last-seen device sequence number; the extension replays its own session-file events after that cursor so device sequence numbers stay continuous.

Status-line copy (spec §4): `"phone connected"`, `"phone is working"`, `"offline"`. (Presence `connected` → "phone connected"; `driving` → "phone is working"; `offline` / no phones → "offline".)

- `packages/pi-hail/src/socket.ts` — `DaemonSocket`: resolve socket path, connect via `node:net`, NDJSON line framing, `register()` round-trip, `send(obj)`, `onMessage(cb)`, `onClose(cb)`, reconnect-with-backoff. Injectable `connect` for tests.
- `packages/pi-hail/src/replay.ts` — `readSessionEvents(sessionFile, sinceSeq)`: read pi's own session file and produce the ordered `{event}` frames after the daemon's `have` cursor, preserving device sequence numbers.
- `packages/pi-hail/src/status.ts` — `presenceToStatus(presence)` → the status-line string; thin `setStatus`/`clear` wrappers over `ctx.ui`.
- `packages/pi-hail/src/session.ts` — `Session`: the pure controller. Holds the register args, the lock state machine, prompt injection, presence handling, refusal, replay, version-mismatch handling. All effects injected: `{ send, sendUserMessage, ui, readSessionEvents, sessionFile }`.
- `packages/pi-hail/src/index.ts` — extension entry: `createExtension(pi, deps?)` and `default (pi) => createExtension(pi)`. Owns-pane gate; captures identity at `session_start`; wires pi events → `Session`; wires `DaemonSocket` messages → `Session`; forwards permission prompts and `input` holding.
- Tests colocated: `protocol.test.ts`, `socket.test.ts`, `replay.test.ts`, `status.test.ts`, `session.test.ts`, `index.test.ts`, `integration.test.ts` (real daemon, gated — Task 11).

**Session controller state (defined once, referenced by later tasks):**
```ts
type Phase = "idle" | "local_turn" | "phone_turn";
type PresenceState = "connected" | "driving" | "offline";
```
- `phase: Phase` — which side owns the current turn. `idle` at rest.
- `pendingPhonePrompt: boolean` — set the moment we call `sendUserMessage` for a phone prompt, so the *next* `turn_start` is attributed to the phone (the `stopHookActive` attribution pattern from pi-tmux-bridge).
- `heldInput: string[]` — local interactive input captured while `phase === "phone_turn"`, re-submitted on return to `idle`.
- `lastPresence: PresenceState` — for status-line idempotence.

**Files:**
- Create: `packages/pi-hail/src/socket.ts`

**Interfaces:**
- Consumes: `encodeLine`, `splitFrames`, `decodeLine`, `RegisterArgs`, `RegisterReply` from `protocol.ts`.
- Produces:
```ts
export interface Duplex { write(s: string): void; on(ev: "data", cb: (chunk: string) => void): void; on(ev: "close" | "error", cb: () => void): void; end(): void; }
export type Connect = (path: string) => Promise<Duplex>;
export function resolveSocketPath(env?: NodeJS.ProcessEnv): string; // $XDG_RUNTIME_DIR/hail/daemon.sock, else $TMPDIR/hail/daemon.sock
export class DaemonSocket {
  constructor(deps: { connect: Connect; path?: string; backoffMs?: number[]; onLine: (msg: unknown) => void; onDown: () => void; });
  register(args: RegisterArgs): Promise<RegisterReply>; // resolves on first reply line; rejects if connect fails
  send(obj: unknown): void;   // best-effort; no-op while disconnected
  connected(): boolean;
  reconnect(): void;          // schedule a reconnect with backoff; caller re-registers in onReconnect
  close(): void;
}
```
The socket owns reconnect scheduling but delegates *re-registration* to the caller (`Session`) via an `onReconnect` callback passed in `deps`, because only the session knows the current register args and replay cursor.
